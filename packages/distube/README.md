# distube

DisTube manages queues and playback. Adapters connect Discord platforms; SourcePlugins resolve canonical media and
prepare fresh playable input.

```ts
import { DisTube } from "distube";
import type { VoiceChannelTarget } from "distube";
import type { Adapter, SourcePlugin } from "distube/integrations";

declare const adapter: Adapter;
declare const sources: readonly SourcePlugin[];
declare const voiceChannel: VoiceChannelTarget;

const distube = new DisTube({ adapter, sources });
const unsubscribe = distube.on("queue.item.started", ({ item }) => console.log(item.song.name));
const pending = distube.play(voiceChannel, "https://www.youtube.com/watch?v=example");
const guildId = "guildId" in voiceChannel ? voiceChannel.guildId : voiceChannel.guild.id;
const registeredQueue = distube.getQueue(guildId);
const { queue, items } = await pending;
console.log(queue === registeredQueue, items.length);

// During application teardown:
unsubscribe();
await distube.dispose();
```

`Song.url` is canonical provider identity, not native audio input. SourcePlugins return a disposable URL resource or an
explicit fallback search request during just-in-time preparation. Players receive only the original item ID and that
prepared resource. Core keeps fallback values private and owns source-resource disposal.

QueueItem IDs and insertion timestamps are generated by core when insertion commits. The optional metadata binding
is readonly and borrows caller-owned contents without cloning or freezing them. One DisTube client registers at most
one live DisTubeGuild per guild. Registration and the first reservation happen before play returns its promise;
queue.created does not imply insertion succeeded. Failed first work deletes its empty queue only when no other
reservation or playback remains, without deleting another caller's queue or releasing adopted voice.

Stop fences and deletes the queue immediately, then joins cleanup. A later play may register a fresh DisTubeGuild
while retaining DisTubeVoice. Volume, repeat and autoplay persist while voice remains connected. Queue deletion
resets selected filters and backend rendering; reset joins terminal cleanup so an old completion cannot alter a
replacement. Failure preserves last acknowledged filters and rendering and reports cleanup causes. Leaving voice
releases its settings; a later voice starts with defaults.

DisTubeGuild, DisTubeVoice and QueueItem are returned public types, not public constructors. Read queue.state for
current, upcoming and status; edit waiting occurrences by ID. DisTubeVoice owns its live channelId and readonly
settings. Move within the guild with voice.move(channel).

onDiagnostic receives structured severity, stage, message, optional plugin, error and detail fields. Delivery is
failure-isolated. Source initialization is synchronous and performs no provider requests; a thenable rejects
construction. Sources and the selected engine share deduplicated lifecycle ownership, with reverse-order disposal.
Call await distube.dispose() to fence work and join cleanup when the application stops.
