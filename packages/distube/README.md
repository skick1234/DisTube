# distube

DisTube manages queues and playback. Adapters connect Discord platforms; SourcePlugins resolve canonical media and
prepare fresh playable input.

```ts
import { type Adapter, DisTube, type Plugin } from "distube";

declare const adapter: Adapter;
declare const plugins: readonly Plugin[];

const distube = new DisTube({ adapter, plugins });
const { items } = await distube.play(
  { guildId: "guild", voiceChannelId: "voice" },
  "https://www.youtube.com/watch?v=example",
);
distube.on("queue.item.started", ({ item }) => console.log(item.id));
```

`Song.url` is canonical provider identity, not native audio input. SourcePlugins return a disposable URL resource or an
explicit fallback search request during just-in-time preparation. Players receive only the original item ID and that
prepared resource. Core keeps fallback values private and owns source-resource disposal.

QueueItem IDs and insertion timestamps are generated by core when insertion commits; callers provide only the Song
and optional metadata. One DisTube client permits one active GuildQueue per guild. Stop deletes the queue and makes its facade stale. A later `distube.play` call may create a fresh queue while reusing
the guild Voice, moving that Voice when the requested channel changes.

`onDiagnostic` receives structured severity, stage, message, optional plugin, error, and detail fields. Delivery is
detached and failure-isolated. Plugin initialization is synchronous; returning a thenable rejects construction.
