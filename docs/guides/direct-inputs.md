---
title: Direct playback inputs
description: Play files, URLs and streams directly on a voice, with seek and cleanup rules.
---

Music commands use `const queue = await distube.play(channel, query)` and queue controls. Direct playback is
useful for an application-owned clip or audio generated by the bot. Join a voice without a queue first, or await
`queue.stop()` to detach the existing queue. Direct `play`, `pause`, `resume`, `stop` and `seek` reject
`INVALID_STATE` while a queue is attached.

```ts
import { createReadStream } from "node:fs";
import { resolve } from "node:path";
import type { DisTube, VoiceChannelTarget } from "distube";
import type { PlaybackResource } from "distube/integrations";

declare const distube: DisTube;
declare const channel: VoiceChannelTarget;
declare const accessToken: string;

const voice = await distube.voices.join(channel);
const clipPath = resolve("clips/welcome.mp3");
await voice.play({ kind: "file", path: clipPath });
if (voice.seekable) await voice.seek(12);
await voice.stop();

const authenticated: PlaybackResource = {
  kind: "url",
  url: "https://audio.example/private.mp3",
  headers: { Authorization: `Bearer ${accessToken}` },
  seekable: true,
};
await voice.play(authenticated);
await voice.stop();

await voice.play({ kind: "stream", stream: createReadStream(clipPath) });
// Core destroys this readable after the backend detaches it.
await voice.stop();
await voice.leave();
```

Queue inputs remain strings, Songs and Playlists. A path passed to `distube.play` is a search query, not a file.
A small application SourcePlugin can map public clip IDs to private fresh resources when clips need scheduling.
Keep private paths and playback credentials out of Song fields, pluginData and events.

| Kind      | Required data                                     | Resource seekability       |
| --------- | ------------------------------------------------- | -------------------------- |
| `url`     | Absolute HTTP(S) `url`; optional string `headers` | Only with `seekable: true` |
| `file`    | Absolute host-platform `path`                     | Seekable by form           |
| `stream`  | Node `Readable` in `stream`                       | Never seekable; one shot   |
| `encoded` | Non-empty `format` and `encoded`                  | Only with `seekable: true` |

The resource union lives at the type-only `distube/integrations` entry. Resources are plain objects, with no
runtime constructor. `voice.capabilities` reports the selected engine's copied `seek`, `resourceKinds` and
`encodedFormats`. `voice.seekable` is false without an active track and otherwise combines engine and resource
support. A supported kind does not imply support for every option of that kind. An engine can also reject
resource options through `supportsResource` before Player creation. For example, Lavalink cannot forward URL
headers even when trusted URL loading is enabled.

## Ownership

Every wrapper and every submitted readable is single-use. A second wrapper around the same readable does not
make it reusable. Create a new resource for every attempt; do not retry a consumed resource after rejection.

Malformed direct input and duplicate submissions remain caller-owned and do not invoke their disposer. A valid
fresh direct resource is consumed before later owner, option or compatibility checks. Even if one of those checks
rejects, that invocation cleans it up. Await the promise to join that cleanup.

Core ends backend access before destroying a readable and invoking optional `dispose()`. Files and inert URL or
encoded values need no no-op disposer. Supply `dispose` for extra owned resources, such as a temporary file;
Players must never call it. Custom cleanup failure does not skip readable destruction. Cleanup completes once
across finish, replacement, cancellation, stop and leave.

## Local decoding and seeking

Official local engines support files, progressive URL bodies and Node readable streams. They require FFmpeg,
an Opus encoder and the adapter's supported encryption implementation. URL requests run through Node HTTP(S)
with copied headers, no redirects and bounded connection/header readiness. Playback streams with backpressure;
it does not buffer the whole track. HLS/DASH and nested URL fetching are unsupported. Header injection,
transport-controlled header overrides and URL userinfo are rejected. Credentials do not enter FFmpeg arguments.

File seeks use decoder input seeking. URL seeks reopen the controlled request and decode/discard audio up to
the requested offset. Large offsets cost time and bandwidth; they are not range requests. Seek and active
filter changes that require restarting the decoder preserve pause intent, volume, filters and track identity.
Streams and nonseekable URLs reject those operations with `UNSUPPORTED` before changing playback. Initial
filters remain supported. If a restart fails after the previous decoder stops, the existing track fails once.

A queue also rejects a seek beyond a known positive Song duration. Missing duration alone does not prohibit seek.
Use the capability readout for UI hints and still handle the operation's rejection.

## Remote playback

Select a remote engine explicitly. For Lavalink, pass the same instance as `engine` and in `sources` when it
also resolves media. It initializes and disposes once. The adapter maintains gateway membership without
starting local audio or checking FFmpeg, Opus or encryption prerequisites.

Lavalink requires server v4.2 or newer within major 4. It accepts `encoded` resources with `format: "lavalink.v4"`.
Headerless URL loading requires `trustedUrlLoading: true` and equivalent destination policy on the node. It
rejects URL headers, files, streams and foreign encoded formats before node work. Local files are not uploaded.
